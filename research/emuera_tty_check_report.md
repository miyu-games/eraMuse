# emuera-tty 検証報告（2026-11-10）

「原作 eraMaou をプログラムから触れるか」の検証。候補：**emuera-tty**（Emuera のターミナル版再実装、Rust、https://github.com/astartes-gaming/emuera-tty 、検証時点 v0.1.1 / master 取得）。検証環境はこの VM（Linux x86_64）。eraMaou はコピー（`/tmp/emuera_check/game`）で作業し、正本には触れていない。

## 結論

**使える。** eraMaou（JP 0.930）は emuera-tty 上で **タイトル→新規開始→初期設定→プロローグ→初期奴隷生成→メイン画面→調教→精算→能力アップ→ターン進行→セーブ/ロード** まで一通り動作した。パースエラー0、実行中の警告・エラー0。原作の表示・挙動を実機なしで確認する検証台として実用になる。

## 対応範囲（README / doc/wiki 実読）

- Emuera 本家に加え **Emuera-EM/EE 拡張**（MAP_*、DT_*、XML_*、VARSETEX、HTML_PRINT の div ボックス等）と Emuera-Anchor の翻訳CSV系まで実装済み。主要検証対象は AnonTW(eratohoTW)、pops-tw(eraNAS)、eraTohoK で「新規・日々・調教・店・地図・セーブが動作、自動プレイ数千手エラーなし」と明記。
- セーブは **Emuera 形式の読み書き双方向**（本家と行き来できる）。
- `--headless`（stdin/stdout の素通しモード）、`--check`（パースのみ）、`--strict`（未対応命令を警告でなくエラー化）、`--vm-debug`、固定シード `EMUERA_SEED` / 固定時計 `EMUERA_CLOCK` があり、**スクリプト駆動の検証にそのまま使える設計**。
- 意図的な本家との差分は `doc/differences.md` に集約（理由つき）。eraMaou に効きそうな差分は見当たらなかった。

## 画面幅について（マスター指摘の切り分け）

- PTY で **220列×50行** と **100列×40行** の両方で TUI モードを実走。どちらもレイアウト崩壊は起きなかった（区切り線は端末幅に追随。タイトル〜キャラ生成画面まで確認）。
- ただし原作の画面設計自体が幅を使う（メイン画面・調教画面の行は約113字幅）。**実ターミナルで原作と見比べる際は最大化（200列以上）が安全**というマスターの見立ての通りで、幅が足りない環境では「崩れている」ように見える余地はある。今回の検証で幅起因と断定できる不具合はなし。
- なお TUI モードは WAIT 等でキー入力を1字ずつ消費するため、行単位で入力を流す headless と入力の食い方が違う。これは本家 Emuera の挙動に沿ったもので不具合ではない。**自動検証は headless が本命。**

## ついでに得た原作実測（eraMuse 側の未決点への回答）

実走画面から直接読めた事実：

1. **原作の調教画面のソース表示に「快F」はある**（最下段に単独行で表示。快Fの珠も存在）。快系は「快C・快V・快A が1行目、快B は下段（不快・抑鬱の隣）、快F は最下段単独行」で、完全な一塊ではない。
2. **原作のソース表示に「疲労」は無い**（体力・気力バーとは別枠。ソース一覧は 快C/V/A・潤滑・恭順・欲情／屈服・習得・恥情／苦痛・恐怖・反感／不快・抑鬱・快B／快F の16項目）。
3. **原作にも奉仕系フィルタは無い**（フィルタは 愛撫[104]・器具[105]・V性交[106]・A性交[107]・SM[108] の5つのみ）。eraMuse 側で「無い」のは原作と**一致**。
4. **複合系コマンドは原作の一覧に一切出ない**（調教画面の列挙は COMABLE を通った基礎コマンドのみ）。派生は内部で起きる形、という従来の読みと一致。
5. **ニプルファック等も一覧に出なかった**（開始直後の表示は 愛撫・キス・手淫・フェラチオ・アナル奉仕・足コキ・スパンキング・何もしない・会話する・服の着脱のみ）。COMABLE の前提で落ちている形が目視でも確認できた。
6. **SHOP の [52]は 5000pts**（原作価格。eraMuse の ÷100＝50 と整合）。

## eraMuse の検証用途への見立て

- **表示形の正本確認**：ステータス並び・フィルタ構成・コマンド列挙条件など、「原作はどう表示するか」をソース読みでなく**実行結果**で確かめられる。今回の 1〜6 のように、読み違いの訂正に直結する。
- **数値挙動の対照**：固定シード＋固定時計で再現性のある入力列を組めば、特定コマンド列のソース増減・精算結果を原作側で採取し、eraMuse エンジンの出力と突き合わせる自動照合が組める（headless の入出力が素通しテキストなので機械処理が容易）。
- **派生の実測補助**：複合派生のような「条件が合うと内部で切り替わる」挙動は、ソース読みより実走で条件を1つずつ変えて観察する方が速い場面がある。
- 限界：作者の主検証対象は AnonTW 系で、eraMaou は「未検証タイトル」側。今回の範囲では問題が出なかったが、深いフロー（ダンジョン・迎撃・陥落イベント等）に入る場合は、行き詰まり箇所を「emuera-tty 側の未対応」と「原作の仕様」のどちらか切り分ける手間が要る。
