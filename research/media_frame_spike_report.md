# メディア枠 /4・/2 ボイス — スパイク実装報告

（2026-11-10。対象：`~/workspace/era_shell_spike/` の殻のみ。Space・PC 転送・実データには触っていない。実装とローカル検証まで。）

## 前提（マスター決定済み、本実装の土台）

- /4 画像は「生成ではなく拾うだけ」。チャット側のミューが画像ファイルを添付して投稿し、殻が /1/2/3 と同じ DOM 監視で拾って /4 窓に表示する。窓は普段は収納し、画像が届いた時だけ出す。
- /2 ボイスは「付いていれば自動で鳴る」。押して再生する形にはしない。
- 画像・音声の生成そのものは殻では持たない。

## 設計判断

### 拾い方（タグ規約は /1〜/3 と同一に統一）

- **/4 の印**：画像投稿のキャプション末尾に ` /4_NNN`（NNN は現在の手番、3桁ゼロ埋め）を付ける。/1〜/3 の末尾タグ規約とまったく同じにし、殻は「今追っている手」のタグだけを探すので、過去の手の画像が混ざらない。
- **/2 ボイスの印**：追加のタグは作らない。セリフ投稿（末尾タグ ` /2_NNN`）に音声が添えられていれば、それがそのままボイスになる。テキスト振り分けと同じ投稿を起点にする。
- **コンテナの特定**：どちらの場合も、まず「テキストがタグで終わる最も内側の要素」を起点にし、そこから祖先を最大10段遡って「メディアを含む最小のコンテナ」を投稿本体とみなす。隣の投稿のメディアを掴む事故を避けるため、大きいラッパーまで遡らない。
- **画像の選別**：コンテナ内の `<img>` のうち表示面積が最大のものを採り、面積 100×100px 未満は対象にしない（投稿者のアバター等の小さい画像が同じコンテナに同居する想定の切り分け）。`<img>` が無ければ、画像拡張子（png/jpg/gif/webp）を指す `<a href>` を拾う。
- **音声の選別**：コンテナ内の `<audio>`（currentSrc / src / 子の `<source>`）を最優先し、無ければ音声拡張子（mp3/wav/ogg/opus/m4a/aac/webm）を指す href / src を拾う。

### 画像の受け渡し（ページ文脈で取る）

- 拾った URL は C# から直接ダウンロードしない。ページ内で `fetch(URL, { credentials: 'include' })` を実行し、ログインセッションの資格情報を乗せて取得する（2段階方式：開始スクリプトが非同期処理を `window.__eraGrab` に置き、ポーリングスクリプトが結果を読む。既存コードのポーリング流儀に合わせた）。
- 取得した画像は canvas で長辺 1600px 上限に縮小し JPEG（品質 0.85）の data URL に正規化してから C# へ渡し、PictureBox に表示する。原画が何 MB でも受け渡し量とメモリに上限が付く。
- フォールバック：fetch が失敗したら、ページ上に既に表示されている `<img>` 本体を canvas に描く。CORS の無い他オリジン画像では canvas が汚染されて toDataURL が例外になり、その旨をログに残す（無言で真っ白にはならない）。
- data: URL の場合はそのまま使う。

### /4 枠の出し方

- オーバーレイ右側にドッキングする幅 340px のパネルとして実装。既定は非表示（収納）。
- 画像が届いたら自動で出現し、キャプションに手番（/4_NNN）を出す。**複数枚は最新優先**：新しい画像が来たらその場で差し替える（履歴一覧は持たない）。
- 「収納」ボタンで畳むと、右端に細い再表示バー（◀ /4）だけが残る。画像を持っていない時はバーも出ない。

### /2 ボイスの受け口

- ページ内に単一の `Audio` 要素（`window.__eraVoice`）を保持し、新しい声が来たら src を差し替えて先頭から自動再生する。再生状態はページ側の状態オブジェクト（playing / blocked / ended / error）に記録し、C# が1回だけ読み取ってログに残す。
- 自動再生ポリシーで弾かれた場合（blocked＝NotAllowedError 等）は**再試行しない**。ポーリングのたびに鳴らそうとする事故を避けるため、メディアは (手番, URL) のキーで一度だけ処理する（画像の取得失敗も同様）。

## 実装範囲

- `MainForm.cs`：
  - 新規 JS 5本：`JsExtractMedia`（/4 画像・/2 音声の抽出）、`JsStartGrab` / `JsPollGrab`（画像取得の開始／結果読み）、`JsPlayVoice` / `JsVoiceStatus`（自動再生／状態読み）。URL は既存流儀どおり JSON 直列化リテラルでのみ埋め込む（`WithUrl` 追加）。
  - 振り分けポーリング（`OnSplitTimerTick`）に `PollMediaAsync` を同居させ、手番追跡・オンライン時のみ動作する既存条件をそのまま使う。
  - `GrabAndShowImageAsync` / `PlayVoiceAsync`：キーで一度だけ実行、結果は全てログに残す。
  - `BuildOverlay` に /4 パネル＋収納バーを追加（ドック順は既存の下部パネル群の内側、区画1〜3 の右）。
- `engine/layout.json`：区画6「メディア枠（/4 画像・/2 ボイス）」を定義文書に追記（機械的に読むコードは無く、文書としての追記のみ）。
- エンジン側の変更はなし。オフライン時はメディア自体が届かないため枠は収納のまま（layout.json に明記）。

## 実機確認リスト（転送後）

1. **画像投稿の実 DOM 形状**：muse.ai に画像を添付して投稿した時、画像が `<img>` で現れるか（背景画像・添付チップ等の別形でないか）。サムネイルと原寸が別要素で同居する場合、面積最大の選別で意図した方を掴むか。アバター等の小画像が 100×100px の閾値で正しく外れるか。
2. **タグを置く場所**：画像投稿にキャプション（テキスト）を付けられるか。付けられない場合、タグ ` /4_NNN` をどこに書けば投稿として成立するか（同手の別投稿にタグだけ書く運用で拾えるか＝その場合コンテナ遡りで画像まで届くか）。
3. **画像 URL の取得可否**：fetch（資格情報つき）で取得できるか。署名付き URL の有効期限、blob: URL の場合の fetch の挙動。フォールバック（表示中 `<img>` の直接描画）で canvas 汚染（SecurityError）が出るか。
4. **ボイス投稿の実 DOM 形状**：チャット側ミューが送るボイスノートが `<audio>` 要素として現れるか、独自プレイヤー（ボタン＋リンク等）か。音声ファイルの URL が src / source / a[href] のどこにあるか（data 属性等なら抽出側の候補に追加が要る）。
5. **自動再生ポリシー**：ログインやページ内クリックの実績がある状態で `play()` が通るか、NotAllowedError で blocked になるか。blocked になる場合、救済策（ページ内で一度ジェスチャをもらう等）を採るかどうかは結果を見て判断する（現状は未実装で、ログに blocked が残るだけ）。
6. **誤拾いの有無**：/2 に音声の無い手で、前後の音声つき投稿を誤って鳴らさないか（最小コンテナ優先の遡りが効いているか）。/4 でも同様に、隣の投稿の画像を掴まないか。
7. **/4 枠の操作感**：出現・収納・再表示バーの動き、PictureBox の Zoom 表示での縦横比の見え方、区画1〜3 との幅の取り合い（画面幅が狭い時の圧迫具合）。
8. **長いボイスの扱い**：再生が次の手に跨いだ場合、現状は次の声が来るまで止めない。そのままでよいか、止める導線が要るか。

## 残課題・割り切り

- メディアのポーリングはコマンド画面（オーバーレイ）表示中のみ動く。チャット層に戻っている間に届いた /2 ボイスは鳴らない（テキスト振り分けと同じ既存条件。運用上は調教中＝オーバーレイ表示中が前提）。
- DOM 形状に依存する部分はすべて「既存の振り分け抽出のパターンからの類推」で、実投稿での確認は実機確認リスト側に寄せた。特に 4（ボイスの DOM）は未知の度合いが大きい。
- 音量調整・再生停止ボタン等の UI は付けていない（マスター指定どおり最小限。新規の声による差し替えのみ）。
