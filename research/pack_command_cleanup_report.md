## 残置候補と理由（1件）

### rest（休ませる）— セッション進行の要

- エンジン本体（engine.ts の疲労ゲート）が `cmdId !== "rest"` と **ID直書きで rest だけを例外**にしている。パラメータ疲労が 100 に達すると rest 以外の全コマンドが「疲労が限界に達している」で弾かれる（ブロック時の文面自体が「休ませるべきだ」と rest を指す）。
- fatigue_src が負のコマンドは rest（−320）のみで、セッション内（＝調教終了を押す前）の疲労回復手段はこれが唯一。反発（stress）を下げる self_effects（−12）を持つ手もこれだけ。
- 現行のセッション形（1セッション＝手数無制限）では疲労100到達は常態であり、削除すると「疲労100＝セッション強制終了」だけが残り、「休ませて続ける」幅が消える。原作に同名コマンドは無いが、これはパック側の疲労パラメータ機構そのものの要として残す。

### 観察（observe）の扱い — 削除に伴う数値幅の喪失（到達不能ではない）

- observe はパラメータ「技巧」（params.skill）を伸ばす現代世界で唯一の手だった（explore の +12 は fantasy で到達不能）。CONVERSION の skill は "0" で、ソースからは一切伸びない。
- params.skill の使われ方：残置コマンド6件の快ソース式のボーナス項（愛撫 `skill*0.15`、クンニ `skill*0.2`、正常位 `skill*0.2` 等）と、射精チェーンの skillLv 倍率。**いずれも倍率・ボーナスであり、解放条件・刻印・ABLUP・陥落条件のどれも params.skill を読まない**（unlock 全式・ORDER_JUDGES・checkFallTraits・abilityGateReason を走査して確認）。
- よって削除しても到達不能になる要素は無い。失われるのは「観察を繰り返して技巧を上げ、愛撫系の数値を伸ばす」というパック独自の育成幅のみで、これは基本否の判断に従い削除側に回した。復活させるなら observe 1件の再追加で足りる（地の文6件・口上24件も削除前バックアップから戻せる）。
