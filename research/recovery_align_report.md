# 回復モデルの突き合わせ — 実施報告

実施：2026-11-09（サブエージェント作業）
対象：ローカルエンジン `~/workspace/era_shell_spike/engine/` と原作 eraMaou JP 0.930（`~/workspace/era_proto/research/eramaou_jp_src/eramaou/`、ERB は CP932 変換して実測）。Space・PC転送・実データには触っていない。
発端：マスターの見立て「基本終わると半分回復、気絶だと3割くらい」「回復は休憩コマンドで半分回復らしい」と、現行実装（午前→午後 max/10、午後→翌日 max/2）の突き合わせ。

## 結論（要約）

- **現行の基本回復率（max/10・max/2）は原作形そのもので、変更は不要だった**。コード変更はしていない（テスト追加のみ）。
- マスターの見立ての「半分」は**夜（日境界）の回復**としては一致するが、日中の区切り（午前→午後）は原作でも max/10 で、「終わるたび半分」ではない。
- **「休憩[199]で回復率が上がる」仕組みは原作に無い**。[199] は回復に一切触れず、ターンを終えるだけ。どの経路で終わっても回復は同一のターン終了処理で付く。
- **「気絶だと3割」という回復率は原作のどこにも無い**。原作では調教対象が体力0以下で終わると回復ではなく**キャラ削除（死亡）**になる。eraMuse の「倒れてもキャラを残す」形は既存の意図的な読み替えで、その後の回復は原作のターン終了式の一般形（1へ引き上げ＋通常回復）がそのまま当たっている（実測：午前区切りで 1＋max/10、夜で 1＋max/2）。
- 非対称（/10 と /2）は読み替えの産物ではなく、**原作自体が1日2スロット（午前/午後）構造で持っている形**。一律化は原作形から外れるため採らない。

## 1. 原作実測（eraMaou JP 0.930）

### 1.1 ターン終了時の回復式 — @EVENTTURNEND（SYSTEM.ERB:154-、回復部 226–305）

`BEGIN TURNEND` のたびに**全キャラ**へ一括適用される。実行順は、EVENT_TURNEND.ERB の @EVENTTURNEND（#PRI）が先に TIME を進め（午前終了→TIME=1、午後終了→翌日処理＋TIME=0）、続いて SYSTEM.ERB 側が回復する。TIME は「進行後」の値で読む（コードコメント「午後の調教後は夜の休みが入るので回復大きい」と整合する読みはこれだけ）。

体力（SYSTEM.ERB:227–274）：

```
SIF BASE:0 < 1
    BASE:0 = 1                          ; まず 1 へ引き上げ
IF TIME == 1                            ; 終わったのは午前（次が午後）
    HEAL = MAXBASE:0 / 10
ELSE                                    ; TIME == 0 ＝ 午後が終わり夜の休みが入った
    HEAL = MAXBASE:0 / 2
;装備効果（W:8=4 で ×(RESULT+1)、W:8=13 で ÷(RESULT+1)）   ※装備システム
;SIF TALENT:314 == 3（吸血鬼） HEAL *= 3                  ※種族
;SIF CFLAG:1 == 2（侵攻中） HEAL /= 30                    ※侵攻システム
;IF CFLAG:503 & 1（休憩フラグ） HEAL *= 2、CFLAG:503 -= 1 ※§1.3
IF TALENT:111（回復早い）
    HEAL *= 2
ELSEIF TALENT:112（回復遅い） || TALENT:256（虚弱）
    HEAL /= 2
BASE:0 += HEAL                          ; MAXBASE でクランプ
```

気力（SYSTEM.ERB:276–308）：侵攻中キャラだけ `MHEAL = MAXBASE:1 / 40`＋装備・気丈/臆病補正の部分回復。**それ以外のキャラは毎ターン終了で全回復**（`BASE:1 = MAXBASE:1`）。

### 1.2 終了経路による差は無い — [199] 休憩の実態（SHOP.ERB @USERSHOP:127–132）

```
ELSEIF RESULT == 199
    ;休憩
    PRINTL あなたは内政に専念し、休憩した……（税金+5%）
    FLAG:9 += 5
    BEGIN TURNEND
```

[199] がするのは **税金フラグ +5 とターン終了だけ**で、回復率・回復フラグへの作用は一切無い。調教（調教終了→AFTERTRAIN→@EVENTEND→BEGIN TURNEND）、侵攻[109]、キャラ情報[101]経由の終了も、すべて同じ TURNEND に合流し、§1.1 の回復がそのまま付く。つまり原作の回復は「休憩を選んだ場合に限る」ものではなく**ターン終了という区切り自体に付く一律の処理**で、率の非対称は「その区切りの向こうに夜があるか」だけで決まる。

「休んで半分回復した」という記憶が成り立つ場面はある：午後のスロットを休憩で終えれば、そのターン終了は日境界＝max/2 の回復になる。ただし因果は「休憩→半分」ではなく「夜→半分」で、午前に休憩しても回復は max/10 のまま。

### 1.3 「休憩フラグ」（CFLAG:503 bit0）の正体

§1.1 で HEAL を ×2 する `CFLAG:503 & 1` はコメントこそ「休憩フラグ」だが、SHOP[199] では立たない。立つのはダンジョン系だけ：

- DUNGEON.ERB:251–255、278–282 — ダンジョン探索パーティが浅い階層へ戻った（帰還した）ときにメンバーへ `CFLAG:503 += 1`
- DUNGEON.ERB:709–747 — キャンプ装備（W:8=18）の効果で就寝時にセット

すなわち「探索から戻って休んだ」印であり、調教・メニューの休憩とは無関係。eraMuse にダンジョンシステムは無いため、この倍率は対象外（後述の欠け参照）。

### 1.4 気絶（体力枯渇）の原作形

- 調教中コマンド終了ごとに @EVENTCOMEND（TRAIN_MAIN.ERB:199-）が `BASE:0 <= 0` を判定 → 調教強制終了（AFTERTRAIN へ）。
- @EVENTEND（TRAIN_MAIN.ERB:241-、該当部 285–298）：`BASE:0 < 1` なら**珠を獲得せず、キャラを削除（DELCHARA）**してターン終了。
- よって調教対象については「倒れた→減率で回復」という経路自体が原作に存在しない。§1.1 の「BASE<1 → 1 へ引き上げ」は、削除されずに残ったキャラ（探索帰還組など）へ一般形として当たるもの。
- 全域を走査しても、回復率としての /3 や ×0.3 の式は存在しない（体力への加算は SYSTEM.ERB:272 の HEAL のほか、アイテム・魔法・研究所等の個別効果のみ）。なお EVENT_NEXTDAY.ERB:483 の `BASE:0 = MAXBASE:0 / 10` は「死んだはずのキャラが朝帰ってくる」復帰イベントの代入で、回復率とは別物。

### 1.5 メニューの流れとの対応

原作の1ターンは「SHOP メニュー（買い物・各種操作）→ 行動（調教／侵攻／休憩など）→ TURNEND（時間進行＋§1.1 の回復）→ 次の SHOP メニュー」。回復は TURNEND の時点、つまり**次のメニューが開く前に**付いている。

eraMuse の読み替え（マスター前提）では、メニューフェーズの「次へ進む」操作が休憩の席にあたり、回復はその操作に付く。現行実装はまさにこの形で、`endSession`（調教終了→メニュー）の時点では回復せず、`proceedToNextSession` → `beginNextSession` で回復が適用される（テストで固定、下記）。原作との見かけの差は「回復済みの値がメニューに表示されるか、次のセッション開始で見えるか」だけで、率と適用回数は一致する。

## 3. マスターの見立てとの照合

- 「基本終わると半分回復」→ **部分的に一致**。半分（MAX/2）は夜をまたぐ区切りだけ。日中の区切りは原作・現行とも MAX/10。「終わるたび半分」に寄せると原作形から外れる。
- 「回復は休憩コマンドで半分回復」→ **原作には無い仕組み**。[199] は回復に無関係（§1.2）。半分の出所は夜の回復。eraMuse では「進行操作＝休憩の席」という読み替えの範囲で、回復は区切りごとに §1.1 の率で付く、が原作との正しい対応。
- 「気絶だと3割くらい」→ **原作に形が無い**（§1.4）。作らない。現行の気絶後回復（午前 1＋max/10＝約1割、夜 1＋max/2＝約5割）は、原作の一般形を「キャラを残す」読み替えに当てた結果として、そのまま据え置く。
- 「非対称（/10 と /2）は読み替えとして妥当か」→ **妥当**。原作の1日は午前/午後の2スロットで、非対称は原作の式自体。セッション区切りで一律にする案、日境界だけ別扱いにする案は、いずれも原作の式（区切りごとに、夜があるかで率が変わる）と等価でなくなる。

## 4. 実施した変更

- **エンジンのコード変更なし**。基本率は既に原作形に一致しており、原作に無い形（気絶3割・休憩での倍増）は作らない方針（原作に無い形は実装せず報告に留める、の指示どおり）。
- **回復テストを新規追加**：`/tmp/eramuse_recovery/recovery_tests.ts`（隔離ホーム `/tmp/eramuse_recovery/home` で実行）。era-engine.exe の再ビルドは不要（コード無変更）。

据え置いた既知の欠け（今回の見立ての範囲外として判断を仰ぐ形に残す）：

- **回復早い／遅い・虚弱の回復量倍率（×2／÷2）**：原作の式には含まれるが未接続。現行は同じ素質を「体力・気力最大 ±500」の換算（職業側数値の殻側適応）で別途効かせており、倍率まで効かせると二重取りになる、というセッション再構成時の据え置き判断が既にある。原作形に寄せるなら「倍率を接続し、±500 換算を外す」がセットで、既存キャラの最大値が変わる（例：回復早い持ちは 2500→2000）ため、今回の見立てには含まれない変更として手を付けていない。
