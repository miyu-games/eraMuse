# rest（休ませる）の再判定 — 実施報告

実施：2026-11-09（サブエージェント作業）
対象：ローカルエンジン `~/workspace/era_shell_spike/engine/` のみ。Space・PC転送・実データ（characters/・logs/・実セーブ）には触っていない。
発端：マスターの指摘「休ませる は基本その時点で終わる想定だと思われる」。前回整理（`pack_command_cleanup_report.md`）の rest 残置根拠が崩れるかを再判定した。

## 結論

- **マスターの読みが正しい。rest は削除した**。カタログは 83件 → **82件**。
- 原作では「休む」は調教中の手ではなく、そのターンで終わる側の仕組み（後述）。現行 rest のような「休ませて同じセッションを続ける」手は原作に無く、削除しても原作形の役目分担（終える＝調教終了、回復＝セッション遷移時）は現行エンジン側に既に揃っている。

## 現行エンジンで rest が実際にしていたこと（削除前の実測）

- 通常のセッション内コマンドとして実行され、**セッションは続く**。コスト体力0・気力0、リソース（体力・気力）には一切触れない。
- 効果はパック独自パラメータへの作用のみ：情愛ソース25、疲労ソース −320（変換式 `fatigue_src × 0.1` で疲労パラメータ **−32**）、自己効果で反発パラメータ **−12**。
- 疲労ゲート（engine.ts）が `cmdId !== "rest"` と rest だけを例外にし、疲労100到達時のブロック文面も「休ませるべきだ」と rest を指していた。つまり rest の「要」という地位は、パック独自の疲労パラメータ機構が自分で作った需要だった。

## 原作 eraMaou 側の確認

- **調教中コマンドに休憩・回復系は無い**。COMF 全走査で体力を戻す（負の LOSEBASE）コマンドは無し。最も近い「何もしない」（COMF55）も気力10を消費しソースを与えるだけの焦らし手で、回復はしない。
- **「休憩」は調教外メニュー（SHOP）の選択肢 [199]** で、選ぶと即 `BEGIN TURNEND` ＝そのターン（午前/午後）を丸ごと終える。「あなたは内政に専念し、休憩した……」と、調教しないでターンを過ごす選択。
- **回復はターン終了時にのみ、全キャラへ一括で**適用される（SYSTEM.ERB の回復処理：体力は MAXBASE の 1/10 または 1/2（時間帯による）、気力も別途回復、休憩フラグで ×2）。現行エンジンの `beginNextSession`（体力 max/10・max/2、気力全回復）はこの形の移植であり、既に一致している。
- 調教中の資源枯渇についても、原作は「続ける」ではなく「終わる」で処理する：@EVENTCOMEND で体力 ≤ 0 なら調教は強制終了（AFTERTRAIN へ）、瀕死時自動終了設定でも同様。
- なお原作には「疲労パラメータ」「反発パラメータ」という概念自体が無い（反発は刻印）。疲労100ゲートも rest の受け皿需要も、パック側機構の内部事情だった。

## 削除した場合の依存の洗い出し

### 疲労100からの脱出経路 — セッション終了で足りる

- 疲労パラメータは上限100でクランプされる（PARAM_DEFS: max 100）ため、超過分が溜まることは無い。
- ゲートは `executeCommand` の中だけにあり、**調教終了（endSession）は op であってゲート対象外**。疲労100でも常に終えられる。
- 日境界（午後→翌日）で疲労 −45 が入るため、100 → 55 となり翌日は必ず再開できる。詰みにはならない（実働で検証済み、下記）。
- 代償として残る挙動：午前のセッションで疲労100に届いた場合、午前→午後の遷移ではパラメータ減衰が無いため、午後のセッションも開始時点でブロックされ、実質そのまま終了して翌日に回す形になる。失うのは最大で「そのセッションの残り＋午後1セッション」。期間は延長可。
  - これは前回整理時に「日次緩和を日境界に残した」設計の帰結であり、rest 削除とは独立した調整ノブ。**今回は変更していない**。気になる場合は「疲労・反発の減衰を全セッション遷移時へ移す」が候補になるが、バランス変更なのでマスター判断待ちとして残す。

### 反発パラメータを下げる経路 — rest 以外に残る

- 変換式自体に減少項がある：`stress = pain×0.06 + fear×0.06 − affection×0.10 − pleasure×0.02`。情愛・快楽系の手は反発パラメータを押し下げる。実測：反発300の状態から会話×3で 300→282（−6/手）、愛撫×3で 300→297。
- 日境界で −10 の減衰もある。
- 反発「刻印」の消去（ABLUP99、屈服の珠）はパラメータとは別層で、従来どおり機能する。rest 削除の影響なし。
- 反発パラメータを読む側（否定の珠のセッション内正増分集計、peak_stress 到達記録、ev_stress イベント）は、いずれも rest の存在を前提にしていない。

### その他の参照

- 疲労パラメータを読むのはゲートと表示サマリーと日境界減衰のみ。解放条件・刻印・ABLUP・陥落条件のどれも疲労/反発パラメータを条件にしていない（全式走査＋テストで確認）。
- rest には BAND_KEY のエントリは無い（既定の trust バンドに落ちていた）。カテゴリ「日常」は rest 専用だったため、CATEGORY_COSTS の「日常」も併せて除去（前回整理で空カテゴリの補完コストを消した流儀に合わせた）。
- 旧セーブの `prevCommandId` 等に rest が残っていても、参照する unlock 式は無く無害。

## 一致／欠け／余計の区別

- **一致**：残置82件は全て原作（eraMaou）対応コマンドになった。「休む＝その時点で終わる、回復は遷移時」という原作の役目分担が、調教終了 op と beginNextSession の回復でそのまま成立する。
