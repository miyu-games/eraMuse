# eraMaou セッション構造・資源・COMABLE 実測メモ

実施：2026-11-08〜09（セッション骨格の原作形への改修の前提実測）
出典：eraMaou JP 0.930（`~/workspace/era_proto/research/eramaou_jp_src/eramaou/`、ERB は Shift_JIS を CP932 変換して読解）

## 1. セッション構造（時間の数え方）

- 表示は `DAY+1 日目`、TIME==0 で「（午前）」、TIME==1 で「（午後）」（TRAIN_MAIN.ERB @SHOW_STATUS）。**1日 = 2セッション（午前・午後）**、1回の調教（BEGIN TRAIN〜調教終了）が1スロットを消費する。
- @EVENTTURNEND（EVENT_TURNEND.ERB、#PRI）：TIME==1（午後が終わった）なら EVENT_NEXTDAY を呼び DAY+=1、TIME=0。TIME==0 なら TIME=1。その後 BEGIN SHOP（メインメニュー）へ。つまり流れは メニュー→調教（午前）→メニュー→調教（午後）→日送り→メニュー。
- 調教の終了は USERCOM の 調教終了[200]（USERCOM.ERB: RESULT==200 → BEGIN AFTERTRAIN）。コマンド回数に上限は無い。
- @EVENTEND（TRAIN_MAIN.ERB、BEGIN AFTERTRAIN の頭）：調教後行為・売却等の後、**CALL JUEL_CHECK**（珠換算＋能力購入ループ）→ BEGIN TURNEND。
- 期間（日数制限）の概念は原作に無い（日付は無制限に進む）。14日は eraMuse 側の枠。改修では「14日 = 28セッション」と再定義する。

## 2. 資源（体力 BASE:0／気力 BASE:1）と倒れる条件

### コマンドごとの消費と気力0の倍化（@SOURCE_CHECK、SYSTEM_SOURCE.ERB:378-406。@SOURCE_CHECK_AUTO にも同形あり）

```
;気力０による上下の処理
IF BASE:1 <= 0
    UP:3 /= 2   ; 潤滑
    UP:4 /= 2   ; 恭順
    UP:5 /= 2   ; 欲情
    UP:7 /= 2   ; 習得
    UP:9 /= 2   ; 苦痛
    UP:13 /= 2  ; 抑鬱
    LOSEBASE:0 *= 2
    LOSEBASE:0 += 80
ENDIF
...（失神チェック・苦痛ダメージの後）
BASE:0 -= LOSEBASE:0
BASE:1 -= LOSEBASE:1
```

- 判定は「そのコマンドの処理時点で気力が既に 0 以下」のとき。体力消費（LOSEBASE:0）が **×2 + 80** になる。気力消費（LOSEBASE:1）は倍化しない。体力・気力とも減算はクランプなし（マイナスになりうる）。
- 同時に、絶頂に絡む UP:0,1,2（快C/V/A）と快B/F・屈従・恥情・恐怖・反感・不快**以外**の PALAM 増加（潤滑・恭順・欲情・習得・苦痛・抑鬱）が半減する。
- 現行エンジンの cupChain にある「気力0で CUP 半減」は部位側の別規則として既存。本改修では上記のソース側半減を、対応の付くチャンネル（affection=恭順／pleasure=欲情／pain=苦痛）にだけ写像する（恥情・恐怖・屈従は原作でも半減対象外）。

### 倒れる（死亡）判定（TRAIN_MAIN.ERB @EVENTCOMEND）

- コマンド終了ごとに `BASE:0 <= 0` を判定 → 「ぴくりとも動かなくなった」→ BEGIN AFTERTRAIN。
- @EVENTEND で `BASE:0 < 1` なら**珠を獲得せず**キャラを削除してターン終了（「調教後に死ぬか臨死状態なら珠を獲得せずに、ターゲットを空にしてターン終了」）。
- 任意設定 FLAG:35==1 では BASE:0 < 500 で自動終了（瀕死自動終了）もあるが、既定の形は上記。
- 失神（PASSOUT.ERB @PASSOUT_CHECK）は資源とは別系統（絶頂・苦痛・恐怖の極端値でランダム発生、調教は続行する）。本改修の対象外。

### 回復タイミング（@EVENTTURNEND、SYSTEM.ERB:154-、全キャラ共通処理）

- 毎ターンエンド（= 毎セッション終了後）に回復する。
- 体力：`BASE < 1` ならまず 1 に引き上げる。回復量 HEAL は、時間帯が進んだ後の TIME で決まる（EVENT_TURNEND.ERB 側の #PRI が先に TIME を進める前提で、コメント「午後の調教後は夜の休みが入るので回復大きい」と整合する読み）：**午前セッション後（次が午後）= MAXBASE/10、午後セッション後（夜・翌日）= MAXBASE/2**。上限でクランプ。
- 気力：通常状態のキャラは**毎ターンエンドで全回復**（`BASE:A:1 = MAXBASE:A:1`。侵攻中キャラだけ MAXBASE/40 の部分回復＋素質補正）。
- 素質：回復早い（TALENT:111）で HEAL ×2、回復遅い（112）・虚弱（256）で HEAL /2。※現行エンジンの「回復早い/遅い → 最大値 ±500」は CHARA_JOB_CHANGE の職業側の数値（MAXBASE ±500）を拾った殻側の適応で、原作の回復早い/遅いは**回復量**に効く。両方を同時に効かせると二重取りになるため、本改修では最大値換算を現行のまま据え置き、回復量倍率は**未接続**として区別する（報告書参照）。
- 射精ゲージ：@EVENTTRAIN（セッション開始時）に MASTER・TARGET・ASSI の BASE:2 を 0 リセット。潤滑も PALAM のセッション内変数として開始時に 0 前提（常時発情 TALENT:271 のみ 潤滑・欲情 3000 で開始）。

### PALAM と精算入力

- ERB 内に PALAM の明示リセットは無い（@EVENTTRAIN が潤滑・欲情を「= 3000」と代入で置く書き方からも、セッション開始時点で 0 の前提）。PALAM は**セッション内の累積**であり、@JUEL_CHECK_MAIN はその**絶対値**を階段換算する（増分ではない）。日次の watermark 差分はパック側の作り。
- @JUEL_CHECK_MAIN の換算：PALAM 0〜15 を共通階段で換算。快系は GOTJUEL = 階段 + EX×1000。潤滑(3)・反感(11)・不快(12)・抑鬱(13) は保有珠に数えない（11〜13 は否定の珠 GOTJUEL:100 へ合算）。否定の相殺は {恭順・欲情・屈服} → {恥情・苦痛・恐怖} の順（現行移植と一致）。

### 購入の場所

- @JUEL_CHECK（TRAIN_MAIN.ERB）は JUEL_CHECK_MAIN の直後に **ABLUP の選択ループ**（SHOW_INFO_EXP / SHOW_JUEL / SHOW_ABLUP_SELECT → INPUT → ABLUPn、RESULT==999 で終了確認へ）を持つ。つまり能力購入は**調教終了後の処理の中**＝メニュー側であり、調教中には開かない。現行の「購入はメニュー側」への移行はこの形に一致する。

## 3. COMABLE（解放条件）

出典：COMABLE.ERB の @COM_ABLE0〜208（+ @V_ABLE）。条件は全て状況系で、**パラメータ数値の閾値ゲートは存在しない**。種別は以下のとおり（カタログ 88 件のうち Maou 対応のある 59 件＝comN 系＋名前付き8件について分類）。

| 条件種別 | 内容 | 現行エンジンでの表現 |
|---|---|---|
| フィルタ | FLAG:25（愛撫系/器具系/V/A/SM）有効時は該当コマンド不可 | 殻側の表示フィルタとして実装済み（実行可否はエンジン側では扱わない。原作では表示と可否が一体） |
| 装備・状態（TEQUIP） | 決闘中(55)・触手調教中(90)・犬(89)・コロシアム(88)・野外(54)・装着中の道具 等 | 対応する状態系が無い → 常に不成立（ブロックしない） |
| 服装 | FLAG:37（着衣モード）+ CFLAG:40/42 の着衣状態 | 服装システム無し → 常に不成立 |
| 汚れ（STAIN） | 汚れ＋助手の素質・能力の複合（助手プレイ時のみ実質） | 汚れ・助手とも無し → 常に不成立 |
| 助手系（ASSIPLAY） | 助手が調教者のときだけ効く ABL・PALAM 条件 | 助手プレイ無し → 常に不成立 |
| 失神中 | TFLAG:899 > 0（失神中は不可のコマンドがある） | 失神システム未移植 → 常に不成立 |
| 素質（対象） | TALENT:122 オトコ・0 処女・135 未熟・273 貞操封印・150/151 等、@V_ABLE（V行為：オトコ/未熟/処女/貞操帯/貞操封印で不可） | キャラ定義は女性・成人前提で該当素質の保持欄が無い → 表現不可として記録（ブロックしない） |

### 移植した能力ゲート（対象側・現行カタログに能力が存在するもの）

ABL 番号：0=C感覚、10=従順、11=欲望、17=露出癖、21=マゾっ気。

- COM7 秘貝開帳：`ABL:10 < 2` で不可 → **従順 ≥ 2**。（処女 && 従順<3 && 露出癖<3 の追加条項は処女・露出癖が無く表現不可、落とした）
- COM33 素股：`PALAM:3 < 2000` で不可 → **潤滑 ≥ 2000**。
- COM46 浣腸器＋プラグ：`ABL:10 + ABL:11 + ABL:17 < 10` で不可 → **従順 + 欲望 ≥ 10**（露出癖は能力カタログに無いため 0 として合算）。別条項 `EXP:1 <= 25`（A経験）は表現不可で落とした。
- COM54 野外プレイ：`ABL:10 <= 2 && ABL:21 <= 2` で不可。マゾっ気は能力カタログに無く 0 と読むと、条項は「従順 ≤ 2」で効く → **従順 ≥ 3**。
- COM57 羞恥プレイ：`ABL:10 <= 1` で不可 → **従順 ≥ 2**。
- COM58 お風呂場プレイ：`ABL:10 <= 1` で不可 → **従順 ≥ 2**。（TALENT:124 がらみの追加条項は表現不可）
- COM59 新妻プレイ：`ABL:0 <= 2` で不可 → **C感覚 ≥ 3**。
- COM80 イラマチオ：`ABL:10 + ABL:11 < 6` で不可 → **従順 + 欲望 ≥ 6**。
- COM87 ピアシング：`ABL:10 < 3` で不可 → **従順 ≥ 3**。

### 表現不可として落とした主なゲート

- 経験ゲート：COM22/23（V経験 == 0 で不可）、COM26〜29（A経験 < 10 で不可）、COM81/82（V/A経験 < 75）、COM83（V/A経験 < 150）。原作の EXP は行為ごとに増える経験カウンタで、現行エンジンのコマンド実行回数（exp）とは尺度が違う（EXPLV 帯と連動）ため、実行回数への読み替えはしない。
- COM44 縄：`ABL:PLAYER:12 <= 2`（調教者の技巧）。調教者側の能力はパラメータ（技巧 0〜1000）しか無く、Lv への換算規則は試作側の対応づけになるため接続しない。
- COM85 放尿：TEQUIP:22（利尿剤の装備状態）/ TALENT:57（おもらし癖）/ TEQUIP:58 の装備状態条件。状態系が無いため落とした（利尿剤コマンド自体はあるが装備状態を持たない）。
- アイテム所持ゲート全般（上記）。

結果：初期状態でロックされるのは上記の能力・潤滑ゲート 9 件のみで、それ以外は最初から実行可（期待形どおり）。

## 4. 能力表示（CHARA_INFO_SHOW）の巡回とレイアウト

- 呼び出し：USERCOM.ERB RESULT==100 → `CALL SHOW_CHARA_INFO(TARGET)`（調教中）。SHOP 側では @CHARA_INFO（CHARA_INFO.ERB）→ 一覧 → @CHARA_INFO_INDIVIDUAL → 同じ SHOW_CHARA_INFO。
- @SHOW_CHARA_INFO（CHARA_INFO_SHOW.ERB）の構成は PRINTW 区切りの **2枚**：
  1枚目＝名前／一人称[7]／体力・気力バー／点線／素質（SHOW_TALENT）／能力（SHOW_INFO_ABL）／刻印（SHOW_INFO_MARK）／経験（SHOW_INFO_EXP）／珠（SHOW_JUEL）／指輪。
  2枚目＝外見・プロフィール（SHOW_DATA / LOOK_INFO / SHOW_APPEARACE：種族・髪・目・肉付き・癖・チャームポイント・家族・生い立ち・好きなもの・現在の格好 等）。
- つまり「能力表示を繰り返し押すと切り替わる」巡回は、調教画面の状態表示 ⇄ シート1枚目 ⇄ シート2枚目という形。現行エンジンには見た目の構造化フィールドが無いため、2枚目は受け皿なしの欠け。殻では巡回を 状態 → シート1枚目 → 状態 の2点巡回として実装し、2枚目は報告書で欠けとして区別する。
- シート1枚目のレイアウト（実物スクショ image-32.png）：名前／一人称（＋再設定）／体力・気力バー／点線区切り／素質を [ ] で折り返し列挙／能力は4列「名前 - NLV」／刻印は「名前：LVn [*..]」ドットゲージ／経験カウンタ／記録行／珠は4列。縦に流れるテキスト＋点線区切りが形。
- 原作の珠は部位別（快C・快V・快A・快B・快F ＋ 恭順・欲情・屈服・習得・恥情・苦痛・恐怖・否定の全13種）だが、現行エンジンは快楽の珠に統合済み（9種）。シートでは現行の珠のまま表示する（経済は変えない。既出の「形が違う」項目）。

## 5. パック独自コマンド（余計候補）の洗い出し

原作の調教コマンド表（TRAIN_MAIN.ERB @P_C の番号表＋ COMF ファイル群）と現行カタログ（gamedata COMMANDS 88 件）を突き合わせた。comN 系 59 件は全て Maou に対応コマンドあり（COMF90 ニプルファック含む）。名前付き 29 件のうち原作対応があるのは 8 件（キスする=6、会話する=56、愛撫=0、胸愛撫=5、クンニ=1、フェラチオ=31、正常位=20、正常位アナル=26）。残り **21 件が原作に対応の無いパック独自コマンド＝余計候補**：

- コミュニケーション系：なでる(pat)、手を握る(hold_hands)、抱き寄せる(hug)
- 日常・接触系：贈り物(gift)、観察(observe)、休ませる(rest)
- 支配・屈辱系：命令(order)、強い調教(train_hard)、露出させる(expose)、焦らす(tease)、ご褒美(reward)
- 特殊・現代：撮影記録(photo_record)、外出(outing)、記録を見せる(show_record)
- 特殊・ファンタジー：ダンジョン探索(explore)、売却査定(appraise)、依頼報告(quest_report)
- 特殊・SF：許可申請を受ける(permission)、記録を視聴させる(view_log)、権限移譲(transfer)
- 特殊・共通：売却交渉(sell_talk)

削除はしない（地の文 546 件・口上 2032 件にこれらのセルが含まれるため、消去は本人の判断待ち）。解放条件については、数値ゲートはパック側の作りとして全て外し、記録系の連鎖（記録を見せる＝撮影記録の実行済み、依頼報告＝売却査定の実行済み）だけは「状況条件」として残した。
