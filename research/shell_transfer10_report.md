## 修正内容：/2 音声再生の方式変更（ウィジェット再生を主経路に）

### 実機で確定していた切り分け（転送⑨後の手023まで）

### 適用した修正（`MainForm.cs` のみ）

- **主経路「ウィジェット再生」を新設**（新 JS `JsPlayVoiceWidget`）：/2 音声の対応付けで掴んだ presentation のコンテナ内にある再生コントロールをプログラムから `.click()` し、ウィジェット自身に再生させる。コントロールの特定は抽出側（`JsExtractMedia`）で行う新関数 `findPlayControl`：勝者メディア要素から祖先を最大6段たどり、要素とコントロールを両方含む最小のコンテナで `button`／`[role="button"]` を探す。判定材料は aria-label／title／テキスト／内包 svg の title 等のラベル（最優先）、play 系クラス、svg の有無の順でスコア付けし、採用理由（`btnVia`、例 `label@up1`）をログに残す。要素参照はページ内に stash（`window.__eraVoiceBtn`／`__eraVoiceBox`／`__eraVoiceBtnSeq`）し、C# へは有無（`btn`）と手掛かり（`btnVia`）だけを返す。再生スクリプトは手番の再確認、クリック前のメディア要素ベースライン採取、保留中 blob fetch の無効化を行ってからクリックする。
- **クリック後の観測**（新 JS `JsVoiceWidgetStatus`）：成否判定は従来と同形式（state／promise／ct 進行／muted／vol／dur をコンテナ内メディアから読み、主要素は再生中 audio → 再生中メディア → stash 要素の順で選ぶ）。加えて観測行を2種追加：`ボイス診断: ウィジェット内メディア:`（コンテナ内全メディアの state／ct／muted／dur 一覧）と `ボイス診断: クリック後に出現したメディア:`（ベースラインに無かった audio/video 要素・URL を文書全体から検出し、scheme を記録。blob の場合は fetch して type とサイズまで記録する）。本物の音声リソースの形を次回ログで確定するための材料。
- **フォールバックは現行経路を残置**：再生コントロールが見つからない場合、またはクリック直前に消えていた場合のみ、従来の順序（吸い出し → 要素直接 → URL）に落とす。クリックが成立した後の成否不良では自動で落とさない（従来通り、失敗は記録して再試行しない）。手番ラッチ（二重発火抑止）は維持。
- **ログ表記**：開始・成否行の `経路` に `ウィジェット再生` が出る。開始行には `ボタンの手掛かり=` も併記される。
