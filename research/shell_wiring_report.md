## オフラインの扱い（補足3の framing で実装）

オフライン用は別物として作っていない。**一式は完全に共通で、違うのはチャット層（流し込み＋/2 介入）が生きているかどうかだけ**：

- 殻はエンジン応答のたびに、`narration1` / `dialogue`（在庫口上）/ `narration3` を区画1/2/3へ**直接表示**する。これはオンライン・オフライン共通の経路。
- オンライン時は同じ文を `/1`・`/3` タグ付きでチャットへ流し込み、振り分けポーリングが投稿から拾い直す（同じ文なので表示は一致）。セリフ区画2は在庫口上が先行表示され、チャット側ミューの `/2` 投稿が来たら差し替わる。
- チャット層が未接続（WebView 未準備）でも、コマンドは地表示のみで最後まで進められる（ログに「オフライン相当」と記録）。
- レイアウト・データ配置は `engine/layout.json` に定義して同居させた。

## 殻側の変更（MainForm.cs）

既存の検証済み挙動（流し込み5段フロー、常時消し、振り分け、オーバーレイ）には手を入れていない。追加のみ：

- **エンジン行**（下部パネル）：「エンジン開始（素体）」「エンジン開始（栞）」ボタン＋接続状態ラベル。開始でコマンド画面が自動で開く。
- **プロセス管理**：`era-engine.exe --home <出力先engine>` を子プロセス起動、JSON 行往復（SemaphoreSlim で直列化、応答タイムアウト20秒、stderr はログへ）、フォーム終了時にツリーごと Kill。
- **区画4（状態）**：snapshot から自動生成（日数・残り行動・フェーズ／体力・気力・射精・潤滑／パラメータ／ソース／珠）。
- **区画5（実コマンド）**：ダミー4ボタンを廃し、エンジン応答の `commands`（82件、カテゴリ見出しつき行）で毎回再構築。有効・無効は**エンジンの unlocked 0/1 フラグのみ**で決定（従来の度数 ×n 表示は実コマンドにも継続）。
- **1手の流れ**：押下 → `execute` → 区画へ即時表示 → ok なら地の文1を `/1` で送信し、検証成功後に地の文3を `/3` で送信（従来の二段送信ポリシー：1通目未確認なら2通目を送らない）。実行不可（ok:false）の手はチャットへ送らない。
- **購入フェーズ UI**：phase="shop" で購入パネルに切替。能力ごとに「Lv→Lv+1（珠ラベル×価格）」ボタン（複数通貨ルートは通貨ごとにボタン、残高不足は無効）、「翌日へ進む」ボタン。nextCost の無い能力（最大到達・購入対象外）は並べない。
- **期間終了パネル**：finished で「続ける（+14日）」「手元に残す」「手放す」を表示（extend / ending op に接続）。

### 修正1：タグの番号制（振り分けが古い投稿を拾う不具合の根治）

- 症状（実機 23:24）：区画表示が過去のテスト投稿を拾い、セリフ／地文3の文字が重なって表示された。原因は抽出が裸タグ ` /1` の末尾一致で、履歴の多いスレッドでは古い候補に張り付くこと。
- 変更：手ごとに連番を振り、`/1_NNN` `/2_NNN` `/3_NNN` の3点セットで同じ番号を共有する（NNN は3桁ゼロ詰め）。
  - 採番は殻側カウンタ `_handSeq`（アプリ実行中は単調増加、エンジンセッションを跨いでも戻さない）。エンジン応答に累計手数の情報は無い（day / actionsLeft のみ）ため、整合先は存在しない。番号を振るのは「実際にチャットへ送る手」だけ（エンジン実行 ok かつ地の文ありの時／テスト送信2回・3回も1手として採番）。
  - 流し込み：地の文1は `narration1 + " /1_NNN"`、地の文3は `" /3_NNN"`（`OnEngineCommandAsync`、`HandTag()` 経由）。
  - 振り分け：`JsExtractTagged` に現在の番号を `__SEQ_LITERAL__` で差し込み、**現在の手の番号と一致するタグの投稿だけ**を拾う。番号なしの旧形式タグは拾わない。同番号の候補が複数あれば文書順で最後（＝最新の投稿）が勝つ。セリフ `/2_NNN` が来たら在庫口上と差し替える挙動は番号一致で維持。手がまだ無い間（`_handSeq == 0`）はポーリング抽出自体をスキップする。
  - オフライン地表示はエンジン応答からの直接表示で番号に依存しない（変更なし）。定義ファイル `engine/layout.json` のオンライン側記述を `/1_NNN` 形式に更新し、矛盾が無いことを確認した（オフライン側の記述にタグ依存は無い）。
- 検証：抽出 JS の単体テスト（DOM スタブ）で「旧番号の投稿・裸タグの投稿は無視され、現行手の /1_042・/2_042 だけが拾われる」ことを確認。全 JS ブロック14件 `node --check` 合格。ローカルビルド 0 エラー。
