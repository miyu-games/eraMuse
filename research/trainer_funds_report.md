# 調教主のお金（残高・初期資金・開始前購入）実装 報告書（2026-11-09）

対象: `~/workspace/era_shell_spike/`（engine/ が正＋殻）。Space・PC転送には不触。
前提: `trainer_profile_report.md`（trainers_state.json＝調教主の永続ストア、trainerSkill／fallenCount 実装済み）。
本人の決め: 「開始前画面で買い物」＋「初期資金を多めに渡しておけばいい」。お金の置き場は調教主側に寄せる。

## 実装内容

### 1. 調教主残高 `funds`（お金の置き場を調教主側へ）
- 永続ストア `trainers_state.json` の各レコードに `funds` を追加。前回の所感
（「寄せるなら残高だけ調教主ストアへ」）をそのまま採用した形。
- セッション状態の `allowance` は trainerSkill と同じ**作業コピー**に位置づけ直した:
`start` でストアから流し込み（新規は TrainerAssignment.funds 経由、再開は link 時）、
保存のたびにストアへ書き戻す。二重管理にはしていない（エンジン内部の参照箇所は無変更）。
- 初期資金: プロフィール（`data/trainers.json`）に `fundsStart` を持たせ、レコードの
初回利用時に種付けする（ストアに funds が無い場合の一度きり。以後はストア値が正本）。
既定は両プロフィールとも **1000**。
- 額の根拠: eraMuse 換算価格（原作÷100）で、ITEM:52(50) を
堕落人数ゲートの届く範囲で数個買っても残り、高額器具（アナル電極 500）や
中価格帯の器具数点を開始前に揃えられる水準。「多めに渡す」という本人の決めに
合わせ、最高額品1点＋技巧数Lv＋消耗品分が同時に賄える最初の切りのいい額とした。
- お小遣い付与（セッション終了 +100）は、作業コピー経由で**調教主残高への加算**に変更。
倒れたセッションでは従来どおり付与されない。

### 2. 開始前購入（ITEM:52 のみ）
- 新規 op `buytrainerskill`: `{"op":"buytrainerskill","trainerId":"myu"}`。
セッション無しで調教主残高から ITEM:52を買える。
- 可否規則はメニュー購入と共通化した（engine.ts に `trainerSkillShopInfo` を新設し、
`shopItemsOf` の技巧Lv分岐も同じ関数へ寄せた）: 価格 50、上限 Lv10 かつ
技巧Lv ≤ 堕落人数 + 1 の間だけ買える、残高不足は「お小遣いが足りない」。
- 進行中セッションが同じ調教主の場合、作業コピー（trainerSkill／allowance）も
合わせて保存する（表示の不整合が出ない）。
- `trainers` op の応答に `funds` / `fundsStart` / `skillShop`（価格・可否・理由）を追加。
- 殻側: エンジン行の調教主コンボの並びに「技巧Lv購入」ボタンを追加。押すたびに
1Lv 分を購入し、結果（Lv・残高）または不成立理由をログに出す。エンジンの
子プロセス起動処理は開始と共用に切り出した（セッション前でもプロセスが立つ）。

### 3. メニュー購入の統一
- メニューフェーズのお金で買う器具類（op `buyitem`）は、従来どおり作業コピー
（allowance）を引くが、その正本が調教主残高になったため、結果として
**調教主残高から引かれる**形に統一された。珠での能力購入（op `buy`）は別系統で不触。
- 区画4の残高表示は snapshot.allowance ＝作業コピー＝調教主残高と一致する
（表示ラベルを「お小遣い（調教主の残高）」に明示）。

### 4. 器具類の開始前購入について（設計判断・提案に留めた分）
- 所持（inventory）がセッション（対象のセーブ）側にあるため、開始前に買った器具の
置き場が定まらない。**最小ラインとして開始前購入は ITEM:52 のみに留めた**
（ITEM:52 は在庫に入らず調教主の技巧Lvへ直接入るため、この問題が起きない）。
- 器具も開始前に買えるようにするなら、候補は2つ:
(a) inventory も調教主側の持ち物に寄せる（原作ではアイテムは主人側の所持品なので
形としてはこちらが近い。ただし対象セーブの持ち運び・候補プールのシート生成など
inventory 参照箇所の棚卸しが要る）、
(b) 開始前購入分は「次のセッション開始時に inventory へ合流する予約」として
調教主ストアに仮置きする。
どちらも今回の範囲外とし、判断は次回に回す。

### 5. 旧データの移行（壊れないこと）
- funds 導入前の `trainers_state.json`（funds 無し）: 初回利用時に fundsStart で
種付けし、技巧Lv・堕落人数はそのまま保持される。
- 調教主リンク導入前の旧セーブ（trainerLinked でない）: 従来の max 合流に
funds を追加。ストア側は種付け後にセーブ側のお小遣い残高と max 合流するので、
旧セーブの累積が消えず、二重計上もしない。

## 差分整理（一致／欠け／余計）

**一致**
- お金の置き場が原作形（所持金は主人＝キャラ0側の持ち物で、対象を跨いで残る）になった。
- 開始前画面（調教主を選ぶ場所）で買い物ができる形が、原作の開始設定→SHOP の流れに寄った。
- ITEM:52 の可否規則はメニュー／開始前で単一の実装（trainerSkillShopInfo）に統一され、
上限（Lv10 かつ 堕落人数+2）は従来どおり。

**欠け**
- 器具類の開始前購入は未実装（上記4の設計判断。inventory の置き場がセッション側のため）。
- 開始前購入（セッション無し時）はキャラ別 oplog に記録先が無い（調教主ストアが正本で
購入結果は応答に返るため実害は無いが、履歴としては残らない）。
- 殻の「技巧Lv購入」ボタンは現在Lv・残高の事前表示を持たない（押下結果はログで確認。
`trainers` op の応答には含まれるので、表示は今後の殻側の判断）。
- exe 再ビルドは未実施（従来どおり PC 転送時に殻と合わせて実施）。

**余計**
- なし。funds の移行規則（種付け＋max 合流）は原作に対応物の無い eraMuse 側の
移行仕様で、README に明記済み。
