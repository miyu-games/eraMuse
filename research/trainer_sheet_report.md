## 1. 器の形

### 定義側: `data/trainers.json`
各調教主が `sheet`（調教師シート）を持つ形にした。既存2枠（default／myu）の内容は不変（性別 female・技巧 0・資金 1000・メモ文そのまま）。

```json
"sheet": { "sex": "female", "skill": 0, "ejacMax": 10000, "traits": [] }
```

| シート項目 | 内容 |
|---|---|
| `sex` | male / female / futanari。旧 `sex` 直置きをシート項目として正式化 |
| `skill` | 技巧Lv の初期値（旧 `skillStart` を統合）。進行中の正本は従来どおり trainers_state.json の trainerSkill で、シート側は種付け値 |
| `ejacMax` | 射精ゲージ上限（既定 10000＝原作の字面）。新設 |
| `traits` | 調教師素質の id 配列。初期は両枠とも空 |

`fundsStart` はお金の種付けでありキャラシートではないため、従来どおりトップレベルに残した。
旧形式（sex / skillStart の直置き、sheet 無し）も読み込み時にシートへ寄せて読む互換を付けた（後述の検証 C で確認）。

### 調教師専用マスタ: `data/trainer_traits.json`（新設）
- id 規則は対象側（traits.json）に揃えた小文字ローマ字スネークケース。
- 収録は原作実測で調教者側に実在する素質 18 件（解放・小悪魔・魅惑・謎の魅力・母性・人妻・父性・小柄体型・未熟・ロリコン・ショタコン・威圧感・サド・鼓舞・舌使い・調合知識・童貞・オトコ）。各項目に原作番号（判明分のみ）と効果メモ、`wired: 0` を持つ。
- 対象側マスタとの共通化はしない（前提報告書の結論どおり。調教師に要る素質が対象側カタログに無い）。
- プロフィールの traits は読み込み時にこのマスタにある id だけに限る（未知 id は落ちる。検証 B で確認）。

### セッション側（engine.ts GameState）
シートの作業コピーを既存の流儀（trainerSex 等と同じ）で追加:
- `trainerTraits: string[]`（sheet.traits の写し）
- `trainerEjacMax: number`（sheet.ejacMax の写し）

スナップショットには従来の平坦な項目（trainerSex / trainerSkill / fallenCount / resources.ejac・ejacMax）に加えて `trainerTraits` と `trainerSheet { sex, skill, ejacMax, traits }` を出す。`trainers` op の応答にも sheet と traits を追加し、従来項目（sex / skillStart）は互換のため残した。

### 永続側: trainers_state.json
変更なし（trainerSkill / fallenCount / funds の3値のまま）。種付けの参照先が prof.skillStart → prof.sheet.skill に移っただけ。素質の獲得経路を作る段階になったら、こちへ traits を足す二層化が次の手（今回は範囲外）。

## 2. 配線済み／器だけの区別

### 配線済み
- **射精ゲージのシート参照化**: `ejacShoot(ejac, max)` とし、発火閾値（上限の倍数）・減算・クランプを全てシートの上限で計算する。呼び出し3箇所（精液中毒の事前段位・精飲絶頂の段位・確定段の発火）は `s.trainerEjacMax` を渡す。表示上限（snapshot の resources.ejacMax）もシート由来に切替。ゲージ現在値の置き場は従来どおり resources.ejac（セッション内変数）で、セッション開始時の 0 リセットも不変。max = 10000 のとき旧形と完全一致（単体テストで 25 値スイープ照合）。
- **技巧Lv のシート統合**: 種付け・trainers op・開始時受け渡しが全て sheet.skill 経由になった（永続側の役割分担は不変）。
- **性別の正式化**: sheet.sex → セッション trainerSex → スナップショット、の経路は従来どおりだが、置き場がシート項目として定義された。

### 器だけ（未配線）
- **素質の効果は全て未配線**。trainerTraits は計算に一切影響しない。@PLAYER_SKILL_CHECK の相互作用群（解放・魅惑・組み合わせ条件ほか）、@COM_ORDER の実行値素質項（魅惑・謎の魅力・威圧感 +6、サド +3、鼓舞 +1）、威圧感の UP 変換、サドの苦痛変換・必須ゲート、舌使い、調合知識のコスト減——前提報告書 §2 の実測分は全て「器に相乗りできる形」にはなったが、今回は配線していない。受け口の無い項（達成感・露出・逸脱は圧縮ソース 7 キーに独立チャネルが無い）も従来どおり欠けのまま。
- **性別を参照する判定は作っていない**。現行カタログ・エンジンを全走査した結果、調教者の性別や装備を前提とするコマンド可否は存在しない（ペニスバンド等のアイテム自体が無い）。実在しないゲートは作らない方針どおり、性別は器の正式化に留めた。将来その種のコマンドが入れば、参照先は trainerSex（シート）になる。

### 殻側
表示の変更なし。殻が読むスナップショット項目（trainerName・trainerSkill・fallenCount・resources.ejac / ejacMax）は全て従来どおりの形で残し、追加は新キーのみ。MainForm.cs の変更は不要だった。
