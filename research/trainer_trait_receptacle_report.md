### セッション側（engine.ts `GameState` / snapshot）
`trainerId` / `trainerName` / `trainerSex` / `trainerLinked`、作業コピーとして `trainerSkill` / `fallenCount` / `allowance`（残高）。`trainers` op の応答も同範囲（＋開始前購入の可否 `skillShop`）。

### 「シート」と呼べるか
呼べない。正確には「プロフィール（静的定義）＋進行度レコード（数値3つ）」で、対象側キャラのシート（personality / traits / initOverrides / look（LookData）/ 状態一式）と比べると、**素質・能力（技巧以外）・外見・一人称の置き場が無い**。性別（sex）は保持のみで、エンジン内に性別で分岐する処理は存在しない（trainer_profile_report の結論を現行コードで再確認）。

### 原作側の対照
原作の MASTER は **Chara0.csv そのもの**＝キャラ0：`番号0 / 名前「あなた」 / 基礎0・1・2 = 10000 / 素質1（童貞）/ 素質122（オトコ）`。つまり原作の調教者は、対象と全く同じ構造のキャラシート（TALENT・ABL・EXP・CFLAG の全スロット）を持ち、@FIRST_SETTING で性別等を変更する形。マスターの認識「調教師もキャラデータを作る形だったはず」は原作について正確。
